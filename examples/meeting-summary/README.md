# 공통 예제: 회의록 요약 계약

이 예제는 문서 계약과 모의 API·Workflow를 확인합니다. 실제 모델·메일·RAG를 호출하지 않습니다. 모의 API가 원문을 돌려주는 것은 AI 요약 품질 검증이 아닙니다.

## 요구사항

대상은 회의록을 가진 직장인입니다. 입력은 text 문자열, 출력은 summary/action_items/message입니다. R-01 정상 텍스트를 제출하면 결과를 확인합니다(T-01). R-02 누락·빈값·공백·타입 오류는 422를 반환하고 재입력을 안내합니다(T-02). R-03 제공자 실패는 502로 안내합니다(T-03). 입력은 저장하지 않으며 실제 외부 전송은 제외합니다. 실제 서비스의 보관 기간·제한 크기는 강사 확인 필요입니다.

## 기능 분해

| F-ID | R-ID | 입력 → 처리 → 출력 | 다음 단계·실패 | 검증 |
| --- | --- | --- | --- | --- |
| F-01 | R-01/R-02 | text:str → trim·검증 → text:str | F-02; 오류면 중단·422 | T-01/T-02 |
| F-02 | R-01/R-03 | text:str → 모의 처리 → summary:str/action_items:list[str]/message:str | F-03; 오류면 중단·502 | T-01/T-03 |
| F-03 | R-01 | 위 응답 필드 → API 표시 → 사용자 확인 | 종료 | T-01 |

## MVP

포함은 F-01~03의 API 정상/오류 흐름입니다. 순서는 입력 검증→모의 처리→응답→검증입니다. 로그인·파일 업로드·실제 모델·발송은 제외합니다. 사용자는 Swagger에서 입력→응답을 확인합니다. 가정은 로컬 API가 첫 검증에 충분하다는 것입니다. 기능 통과는 T-01~03으로 판단합니다.

AI 품질 평가의 고정 입력: `11월 6일 회의에서 예산 100만원을 유지하고 민수가 11월 10일까지 자료를 준비하기로 했다.` 필수 사실은 두 날짜·금액·담당자·결정이며, 없던 결정이나 담당자를 만들면 실패입니다. 출력의 근거를 원문과 대조하고 사람이 판정합니다. 실제 모델 검증은 미실행입니다.

## 구조·계약

`api.py`의 Schema는 검증, route는 HTTP 변환, 주입된 service는 처리 책임입니다. 수업용 한 파일 예제이며 실제 프로젝트 분리는 `project-structure-template.md`로 설계합니다. 상태는 요청→검증→처리→성공 또는 실패이며 요청 후 저장하지 않습니다. Content-Type은 application/json; POST /api/summarize; 성공 200; 입력 검증 422(detail 배열); 제공자의 타임아웃·연결 실패·요청 거부·사용 불가능한 응답은 502(detail 문자열), 예상하지 못한 내부 버그는 500입니다. SDK 연동 어댑터는 제공자 오류를 `ProviderError`로 변환합니다. 502 detail은 `Summary provider unavailable`이며 내부 버그에는 기본 `Internal Server Error`를 반환합니다. 화면은 MVP에서 제외하고 Swagger로 확인합니다.

## 실행·검증·문서 판정

Kit 루트에서 선택 의존성 `fastapi`, Pydantic v2, `httpx`, `uvicorn`을 준비한 후 `python scripts/verify.py --api`로 모의 API·Workflow를 검증합니다. 수동 확인은 이 폴더에서 `python -m uvicorn api:app`을 실행하여 /docs에 고정 입력과 오류 입력을 넣습니다. 수동 서버 시연은 검증 보고서에 별도 기록합니다.

문서 계약은 모의 MVP 범위에서 통과, 실제 서비스는 모델·입력 제한·보관 기준 확인 필요입니다. 담당은 강사, 실제 AI 실습 전에 결정합니다. 실제 AI 품질이 검증되기 전 AI 서비스 완료로 판정하지 않습니다. 결과와 환경은 `docs/verification-report.md`에 기록합니다.

`workflow.py`는 재시도 상한과 중복 차단의 모의 예제입니다. ledger는 메모리 안에만 있으므로 프로세스 재시작이나 동시 요청에 대한 운영 보장은 없습니다. 실제 외부 작업에서는 영속 저장·동시성 제어·결과 조회 또는 도구의 멱등성 키가 필요합니다.
