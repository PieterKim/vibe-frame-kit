## 요구사항 정의서
여기에 요구사항 정의서를 붙여넣어줘.

## 기능 분해 기준
- 기능은 너무 크지 않게 구현 가능한 작은 단위로 나눠줘.
- 각 기능의 입력, 처리, 출력을 구분해줘.
- API 기능과 AI Agent 기능을 구분해줘.
- MVP 기능과 후순위 기능을 구분할 수 있도록 우선순위를 표시해줘.

## 산출물 형식
다음 표 형식으로 작성해줘.

| 대분류 | 세부 기능 | 입력 | 처리 | 출력 | 구현 우선순위 | 관련 Agent/API |
| --- | --- | --- | --- | --- | --- | --- |

마지막에는 추천 구현 순서를 간단히 정리해줘.

## 공통 산출물 요청
`$function-breakdown`를 사용하고 `templates/function-breakdown-template.md`를 최종 필수 구조로 작성해줘. 앞서 제공한 문서는 재사용하고, R-ID → F-ID → MVP → 계약 → T-ID 연결을 유지해줘. 예외·실패 흐름·AI 품질(해당 시)과 미정 사항을 빠뜨리지 마. 마지막에 단계 판정과 근거를 적고 계획 요청에서는 코드 생성이나 다음 단계 진행을 하지 마.
