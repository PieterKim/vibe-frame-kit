# 팀 협업과 발표

## 작은 변경과 통합

팀이 브랜치 규칙과 담당 기능 F-ID를 정합니다. 시작 전 작업 트리와 다른 사람의 변경을 확인합니다. PR에는 문제와 바뀐 동작, 연결 R-ID/F-ID/T-ID, 실제 검증과 미실행 이유를 적습니다. 리뷰 후 통합하고 API·데이터 계약이 연결되는 흐름을 확인합니다. 충돌 시 다른 사람의 코드를 임의 폐기하지 않습니다. push·PR·merge는 요청한 범위에서만 합니다.

## 발표와 제출

`templates/final-report-template.md`에 문제·사용자·MVP 포함/제외·구조·실행 방법·테스트와 한계를 적습니다. 팀원별 실제 기여를 커밋·PR·문서 등 근거로 연결합니다. 정상·오류 시연 절차와 스크린샷, 저장소 기준 버전, 자체 평가·미완료 작업을 포함합니다. 모의 AI 시연과 실제 AI 시연을 구분합니다.

## 로그 공유

재현 명령·예외 유형·호출 흐름·관련 코드는 유지하되 Authorization 헤더, 쿠키, API 키, 토큰, 비밀번호, 메일 주소와 개인 문서 내용은 가립니다. 자동 가림 뒤에도 사람이 확인합니다. 실제 비밀값은 예제나 보고서에 다시 쓰지 않습니다.
